# kivagram v1 (lib/tg.k) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Стоп-кран:** работа начинается ТОЛЬКО по явному приказу пользователя. План утверждён как «порядок действий и решения»; готовый код в плане намеренно отсутствует — каждое решение описано так, чтобы реализация была однозначной.

**Goal:** Telegram Bot API библиотека, написанная на чистой Kiva: long-polling бот с диспетчером хендлеров, собирается склейкой `lib/tg.k` с файлом бота.

**Architecture:** Синхронный HTTP через `popen`+`curl` (libc, без внешних линковок). Ответы разбирает dot-path JSON-сканер (`tg_get(resp, "result.0.text")`) без построения дерева. Bot/Ctx/Handler — «слоты» (глобальные/выделенные массивы слов с фиксированными индексами), наружу выдаются только функции-аксессоры: точечного доступа в Kive нет. Хендлеры — реестр пар «фильтр fn-указатель → хендлер fn-указатель» (работает на компиляторе с PR #2 «function pointers»).

**Tech Stack:** Kiva (тулчейн из форка `crimbrodev/kivac-plus`, master ≥ `60ca869`: фикс функций + UTF-8 идентификаторы + лимиты строк), curl в PATH, libc (popen/fgets/malloc).

## Архитектурные решения (приняты, не пересматриваются в v1)

1. **Синхронность вместо асинхронности.** Весь async-механизм ggram (промисы+корутины, ~440 строк) существует из-за колбэко-версионного HTTP. `popen` блокирующий → промисов нет, отправки строго в порядке вызова, контракт хендлера тривиален.
2. **POST-тело — через временный файл + `curl -d @файл`.** Текст сообщения может содержать кавычки, `$`, переводы строк; шелл-экранирование — источник уязвимостей и багов. Временный файл (`tg_req<pid>`) удаляется на ВСЕХ путях, включая ошибки записи/запуска curl.
3. **JSON-ответы: dot-path сканер**, не дерево. Паттерн доказан двумя независимыми проектами (Zig tgz, bashbot). Указатели возвращаются внутрь буфера ответа; жизнь — до следующего вызова API. Ошибка поиска — глобальный флаг `tg_last_err` (0 — ок, иначе код).
4. **Параметры запросов — слот-билдер.** Свои variadic-функции в Kive невозможны (грамматика — фиксированный список аргументов). Поэтому `tg_param_str/num/json` дописывают пары в буфер-билдер, вызов собирает `{...}`.
5. **Bot/Ctx/Handler/Buf — слоты с ИНДЕКСАМИ СЛОВ** (слово = 8 байт; индекс i ↔ байтовое смещение 8*i). Схема в разделе «Схема слотов» фиксируется и не меняется. Пользовательский код не видит индексов — только аксессоры (`tg_text(ctx)` и т.д.).
6. **Контракт хендлера:** `fn(ctx)`, последнее выражение = возврат; `0` — прервать цепочку хендлеров (аналог `return false` в ggram), `1` — продолжить. Исключений в Kive нет — падение хендлера = падение процесса; изоляции, как в pcall у ggram, НЕТ (документируется в README).
7. **Строчные буферы:** `tg_scratch()` — один статический буфер процесса (2048 слов = 16 КБ) как РАБОЧЕЕ пространство форматирования (вызовы `sprintf`, сборка тел/URL). Строковые поля Ctx копируются в приватный буфер слота Ctx (слот 16) и стабильны всю диспетчеризацию — `tg_send_text` внутри хендлера не затирает данные следующего хендлера (фиделити ggram, где ctx — декодированная таблица). Buf-слоты (растущие, ×2 через malloc/memcpy/free) — для HTTP-ответов и params.
8. **Offset — файл `tg_<botid>.offset`**, записывается **после КАЖДОГО обработанного апдейта** (`update_id + 1` этого апдейта); на пустом ответе не пишется. Семантика — at-least-once: падение между обработкой и записью ⇒ повторная доставка, хендлеры должны быть идемпотентны (у ggram наоборот — теряются). Бэклог до 24 ч при первом запуске (offset=0) обрабатывается целиком — нормально.
9. **Ошибки:** ни один путь не падает. Транспорт/API-ошибка → флаг + `bot.on_error` (fn-указатель, дефолт-принтер). 429 → авто-sleep по `retry_after`, максимум 3 попытки. 409 в поллинге → `deleteWebhook`, «terminated by other getUpdates» → стоп.
10. **v1 = один файл `lib/tg.k`** (склейка с ботом, никаких модулей — их в Kive нет). Тесты — самостоятельные `.k`-файлы в `tests/`. **Все символы библиотеки (включая внутренние) — с префиксом `tg_`**, иначе коллизии при склейке с кодом пользователя.
11. **Правило матчинга хендлеров:** `подходит := (h.kind == 0) || (h.kind == kind_апдейта)`; kind=0 (UPDATE) ловит всё. Встроенный фильтр сахара — уточняющая проверка ПОСЛЕ этого правила (CMD дополнительно сверяет имя команды).
12. **Командные сообщения не попадают в TEXT-хендлеры** (kind команды = 2 исключительно). Это сознательное расхождение с ggram (там `bot.text` ловит и команды) — фиксируется в README.

## Языковые ограничения Kiva (проверено компилятором; обязательны при реализации)

- **Вызов fn-указателя — только через локальную переменную:** `auto fp; fp = <слот или имя>; fp(args);`. Прямой вызов через глобальный слот или глобальную fn-переменную (`handlers[0](x)`, `gfp(x)`) → SEGV. Чтение fn-указателя в локальную переменную — работает.
- **Порядок определений:** функция, используемая как значение (хендлер/фильтр/on_error), должна быть определена текстово ДО первого такого места — иначе компилятор отдаёт мусорный указатель → SEGV. В тестах и примерах: все функции-хендлеры — текстово перед `main`.
- **Вызов принимает ≤6 аргументов, определение — ≤6 параметров.** Седьмой и дальше аргументы молча превращаются в 0 (НЕ ошибка компиляции) — формат-строка printf + не более 5 значений.
- **`&&`/`||` в языке нет** (лексер их не выдаёт — разбирает как одинарные `&`/`|`). `&`/`|` — уровень P4: связывают плотнее сравнений и сдвигов, скобки обязательны (`(status >> 8) & 0xFF`). «X, а если 0 — значение по умолчанию» — ветвлением: `if n sleep(n); else sleep(5);`, НЕ `sleep(n|5)` (это битовый OR).
- **Глобальный массив в позиции значения — это его ПЕРВОЕ СЛОВО, а не адрес:** в libc и внутренние функции — всегда `&buf`; `fgets(buf, ...)` → SEGV, `fgets(&buf, ...)` → ок. Чтение байта: `@8 slot` или `@8 *(&buf+i)`; `@8 &slot` компилируется в мусор. Запись байта: `*(&buf+i) !8 c`.
- **Строковые литералы:** влившийся в master форка коммит `60ca869` поднял лимиты (один литерал ≤65000 байт, суммарный пул 1 МиБ с ЯВНОЙ ошибкой компилятора при переполнении). Формальный лимит имени — 126 байт (~63 русских символа) — не лимит на практике. Длинные строки (curl-команды с URL/токеном) по-прежнему собираем фрагментами через Buf/sprintf — не из-за лимита, а ради корректной сборки `<url>` из частей.
- **`kivaa` возвращает exit 0 даже при ошибке nasm/cc/ld** (проверяет только WIFEXITED, не WEXITSTATUS) — успех сборки = `test -x <бинарник>`, НЕ exit-код.
- **`kivac input.k output.ir` — только два файла-аргумента** (stdin не поддержан); без `global main` линковка падает `undefined reference to 'main'`.
- Имя ≤126 байт (~63 русских символа) — на практике не лимит. Ключевые слова на русском не нужны: `while/if/for/break/continue/return/else if` реализованы (в op.txt помечены †Not implemented — устарело).

## Схема слотов (индексы слов; слово = 8 байт; фиксируется, не меняется)

**Bot:** 0 token*, 1 base_url*, 2 bot_id, 3 username*, 4 handlers*, 5 handlers_len, 6 handlers_cap, 7 on_error fn*, 8 offset, 9 offset_file*, 10 last_resp*, 11 polling_flag (1 — крутится; `tg_stop` сбрасывает).

**Handler:** 0 name*, 1 kind (0=UPDATE,1=TEXT,2=CMD,3=CALLBACK), 2 filter fn*, 3 handler fn*. Слот = 4 слова.

**Ctx:** 0 bot*, 1 upd_raw*, 2 kind, 3 chat_id, 4 msg_id, 5 from_id, 6 from_name*, 7 text*, 8 command*, 9 target_bot* (имя бота из `/cmd@bot`), 10 mine, 11 exclusive, 12 args*, 13 cbq_id*, 14 cbq_data*, 15 inline_msg_id*, 16 strbuf* (приватный строковый буфер ctx, внутреннее).

**Buf (= Params):** 0 ptr*, 1 len, 2 cap.

**Таблица аксессоров Ctx (закрытый список):** `tg_bot_of`, `tg_raw`, `tg_kind`, `tg_chat_id`, `tg_msg_id`, `tg_from_id`, `tg_from_name`, `tg_text`, `tg_command`, `tg_target_bot`, `tg_mine`, `tg_exclusive`, `tg_arg(ctx,n)`, `tg_cbq_id`, `tg_data`, `tg_inline_msg_id`. Всё остальное через `tg_raw(ctx)` + `tg_get`.

**Сахар регистрации (семейство `tg_on_*`, чтобы не коллидировать с аксессорами):** `tg_on(bot,name,filter,fn)` — примитив; `tg_on_update`, `tg_on_text`, `tg_on_command`, `tg_on_callback`, `tg_on_message` (не-текстовые сообщения: filter «есть message без text»). Имена хендлеров — ОБЩИЙ неймспейс бота, префиксы не добавляются (в отличие от ggram): `tg_on_command(bot,"start",...)` и `tg_on(bot,"start",...)` — одна и та же запись.
