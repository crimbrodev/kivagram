# kivagram v1 (lib/tg.k) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Стоп-кран:** работа начинается ТОЛЬКО по явному приказу пользователя. План утверждён как «порядок действий и решения»; готовый код в плане намеренно отсутствует — каждое решение описано так, чтобы реализация была однозначной.

**Goal:** Telegram Bot API библиотека, написанная на чистой Kiva: long-polling бот с диспетчером хендлеров, собирается склейкой `lib/tg.k` с файлом бота.

**Architecture:** Синхронный HTTP через `popen`+`curl` (libc, без внешних линковок). Ответы разбирает dot-path JSON-сканер (`tg_get(resp, "result.0.text")`) без построения дерева. Bot/Ctx/Handler — «да-слоты» (выделенные массивы слов с фиксированными смещениями), наружу выдаются только функции-аксессоры: точечного доступа в Kive нет. Хендлеры — реестр пар «фильтр fn-указатель → хендлер fn-указатель» (работает на компиляторе с PR #2 «function pointers»).

**Tech Stack:** Kiva (тулчейн из форка `crimbrodev/kivac-plus`, master ≥ `1dc7642`: фикс функций + UTF-8 идентификаторы), curl в PATH, libc (popen/fgets/malloc).

## Архитектурные решения (приняты, не пересматриваются в v1)

1. **Синхронность вместо асинхронности.** Весь async-механизм ggram (промисы+корутины, ~440 строк) существует из-за колбэко-версионного HTTP. `popen` блокирующий → промисов нет, отправки строго в порядке вызова, контракт хендлера тривиален.
2. **POST-тело — через временный файл + `curl -d @файл`.** Текст сообщения может содержать кавычки, `$`, переводы строк; шелл-экранирование — источник уязвимостей и багов. Записали тело в файл, отдали curl'у ссылкой. Файл одноразовый, удаляется сразу после вызова.
3. **JSON-ответы: dot-path сканер**, не дерево. Паттерн доказан двумя независимыми проектами (Zig tgz, bashbot `UPD["result,chat,id"]`). Указатели возвращаются внутрь буфера ответа; жизнь — до следующего вызова API (документируется).
4. **Параметры запросов — слот-билдер.** Свои variadic-функции в Kive невозможны (грамматика — фиксированный список аргументов). Поэтому `tg_param_str/num/json` дописывают пары в буфер-билдер, вызов собирает `{...}`.
5. **Bot/Ctx/Handler — слоты с фиксированными смещениями**, ровно как `funcs`-таблица в компиляторе kiva.k. Пользовательский код не видит смещений — только акцессоры (`tg_text(ctx)` и т.д.).
6. **Контракт хендлера:** `fn(ctx)`, последнее выражение = возврат; `0` — прервать цепочку хендлеров (аналог `return false` в ggram), `1` — продолжить.
7. **Строковые буферы:** один статический `tg_scratch()` (~16 КБ) + растущие Buf-слоты (×2 через malloc/memcpy/free). Жизненный цикл документируется, утечек нет.
8. **Offset — файл `tg_<botid>.offset`**, сохраняется **после** обработки апдейта (ggram сохраняет до — теряет апдейты при падении).
9. **Ошибки:** ни один путь не падает. Транспорт/API-ошибка → флаг + `bot.on_error` (fn-указатель, дефолт-принтер). 429 → авто-sleep по `retry_after` с лимитом попыток. 409 в поллинге → `deleteWebhook`, «terminated by other getUpdates» → стоп.
10. **v1 = один файл `lib/tg.k`** (склейка с ботом, никаких модулей — их в Kive нет). Тесты — самостоятельные `.k`-файлы в `tests/`.

## Границы v1 (сознательно вне скоупа)

Multipart/отправка файлов с диска (в v2 — через `curl -F`, уже заложен дизайн), webhooks, сессии/kv-хранилище, медиагруппы, стикеры, voice/videoNote, русские ключевые слова, свои variadic.

## Схема слотов (смещения фиксируются здесь и не меняются)

- **Bot** (слот, слова): 0 token*, 1 base_url*, 2 bot_id, 3 username*, 4 handlers*, 5 handlers_len, 6 handlers_cap, 7 on_error fn*, 8 offset, 9 offset_file*, 10 last_resp*, 11 scratch_used (флаг), 12 reserved...
- **Handler** (фиксированный слот, как `funcs`, 128 байт): 0 name*, 4 kind (0=UPDATE,1=TEXT,2=CMD,3=CALLBACK), 8 filter fn*, 12 handler fn*.
- **Ctx** (слот): 0 bot*, 1 upd_raw*, 2 kind, 3 chat_id, 4 msg_id, 5 from_id, 6 from_name*, 7 text*, 8 command*, 9 args*, 10 cbq_id*, 11 cbq_data*, 12 reply_chat_id.
- **Buf** (слот): 0 ptr*, 8 len, 16 cap.
- **Params** = Buf (тот же слот).
